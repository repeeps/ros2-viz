PART E · 공간·시스템 — CH 14

시스템 구성 — 같은 노드 여럿 띄우기

실제 시스템은 노드가 수십 개예요. 이걸 하나하나 손으로 켤 순 없죠. ROS2엔 한 시스템을 한 번에 정의하고 띄우는 도구들이 있어요. launch는 "이 노드들을 이런 설정으로 같이 켜라"는 대본이고, 네임스페이스는 같은 노드를 다른 이름 공간에 띄워 충돌 없이 여러 개 굴리게 하며(예 /left, /right 카메라), 리매핑은 노드 코드를 안 고치고 토픽 이름을 갈아 끼우고, 파라미터는 같은 노드의 동작을 바꿔요(해상도·주기 등). 덕분에 같은 노드 하나를 여러 역할로 재사용할 수 있어요.

Step 00 — Namespaces

같은 노드를 여러 개 — 이름 공간으로 구분

카메라 드라이버 노드 하나를 두 번 띄워 왼쪽·오른쪽 카메라로 쓰고 싶어요. 그냥 띄우면 이름이 겹쳐 충돌해요. 네임스페이스를 주면 토픽·노드 이름 앞에 접두사가 붙어(/left/…, /right/…) 깔끔히 분리돼요. 추가 카메라 버튼을 눌러보세요 — 같은 노드가 서로 안 부딪히며 늘어나요.

→ 같은 코드(노드)인데 네임스페이스만 달리해 여러 인스턴스로. 손으로 이름을 바꿀 필요가 없어요.

Step 01 — Remapping

리매핑 — 코드는 그대로, 토픽 이름만 갈아끼우기

인식 노드는 코드상 /image를 구독하게 짜여 있어요. 그런데 실제 카메라는 /front_cam/image로 발행해요. 코드를 고칠까요? 아니요 — 리매핑으로 "이 노드의 /image를 /front_cam/image로 읽으라"고 실행 시 연결만 바꿔요. 리매핑을 켜고 끄며 연결이 이어졌다 끊겼다 하는 걸 보세요.

→ 리매핑 덕에 범용 노드(/image 구독)를 어떤 카메라 토픽에든 붙일 수 있어요 — 재사용성의 핵심.

Step 02 — Parameters & launch

파라미터로 동작을 바꾸고, launch로 한 번에

같은 카메라 노드라도 파라미터(해상도·주기)를 달리하면 다르게 동작해요. launch 파일은 이 모든 걸 — 어떤 노드를, 어떤 네임스페이스·리매핑·파라미터로 띄울지 — 한 대본에 적어 명령 한 줄로 전체 시스템을 올려요. 파라미터를 바꿔보고, 아래 launch 대본이 어떻게 조립되는지 보세요.

→ launch 한 파일 = 시스템 전체의 설계도. 노드·이름·연결·설정이 한눈에 모여요.

Step 03 — Takeaways

정리 — 시스템 구성

네임스페이스로 같은 노드를 여러 인스턴스로, 리매핑으로 코드 수정 없이 토픽을 갈아끼우고, 파라미터로 동작을 조정하고, launch로 전체를 한 번에 — 이 넷이 ROS2 시스템을 재사용 가능하고 관리 가능하게 만들어요. 이제 배운 모든 조각이 모였어요. 마지막으로 이걸 하나의 빈피킹 시스템으로 엮어볼게요.
